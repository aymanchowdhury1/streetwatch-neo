STREETWATCH NEO — START HERE (BEGINNER SETUP)
==============================================

IMPORTANT SECURITY NOTE
-----------------------
This complete local ZIP includes the original .env, firmware/StreetWatchESP32/config.h,
and streetwatch.db because you requested the local files back. These files are excluded
by .gitignore and MUST NOT be committed or uploaded to a public repository.
The original ESP32 token was present in the supplied archive and must be treated as
exposed. Revoke/replace it in the website before using the rover remotely. Rotate any
other credentials if they were reused elsewhere.

PART A — PREPARE THE PROJECT
----------------------------
1. Download and extract streetwatch-neo-complete.zip.
2. Keep the extracted folder named streetwatch-neo.
3. Do not delete .env or streetwatch.db from your own computer; they are your local
   configuration and local database.
4. The real firmware config.h is included for local reference/compatibility. The new
   firmware setup portal stores per-device Wi-Fi/server/device settings in ESP32 NVS.
   Use the portal for normal configuration; do not commit config.h.

PART B — PUBLISH TO GITHUB USING GITHUB DESKTOP
------------------------------------------------
1. Create/sign in to GitHub at https://github.com/.
2. Create a NEW EMPTY repository named streetwatch-neo. Private is recommended.
   Do not initialize it with another README or .gitignore.
3. Install GitHub Desktop: https://desktop.github.com/ and sign in.
4. In GitHub Desktop choose File > Add Local Repository and select the extracted
   streetwatch-neo folder. If it is not a repository, choose Create a Repository and
   use that folder as the local path.
5. Before committing, inspect the Changes list. These MUST NOT appear as staged files:
   .env
   firmware/StreetWatchESP32/config.h
   streetwatch.db
   __pycache__ folders / *.pyc
   uploads or private keys
   The repository .gitignore excludes these. Do not force-add them.
6. Commit the tracked source files with a message such as:
   Prepare StreetWatch Neo for Render and ESP32 AP setup
7. Click Publish repository and select the GitHub repository you created.
8. Verify the repository page contains source code and documentation, but not .env,
   config.h, streetwatch.db, tokens, passwords or Python cache files.

PART C — DEPLOY ON RENDER
-------------------------
1. Sign in at https://render.com/ and connect your GitHub account.
2. Choose New > Blueprint and select the streetwatch-neo repository. Render reads
   render.yaml. Alternatively create a Python Web Service with these settings:
     Build: pip install -r requirements.txt
     Start: gunicorn app:app --bind 0.0.0.0:$PORT --workers 1 --threads 4 --timeout 120 --access-logfile - --error-logfile -
     Health check: /healthz
     Region: Singapore if offered; Plan: Free for initial tests.
3. Set environment variables in Render:
     INITIAL_ADMIN_USERNAME = a username you choose
     INITIAL_ADMIN_PASSWORD = a new unique password (at least 12 characters)
     DATABASE_URL = your PostgreSQL connection URL
     COOKIE_SECURE = true
   SECRET_KEY and WTF_CSRF_SECRET_KEY are generated by render.yaml. If creating the
   service manually, set two different random secrets, each at least 32 characters.
4. Create/configure PostgreSQL separately and use its connection URL as DATABASE_URL.
   Check the current Render pricing/expiry policy before relying on a free database.
   Render Free web-service disk is ephemeral; do not use local SQLite as hosted storage.
5. Deploy. Open https://YOUR-SERVICE.onrender.com/healthz. Expect status=ok.
6. Open the site and sign in with the admin username/password configured above.
7. If you want to import existing traffic/alert records from your local SQLite database,
   follow RENDER_DEPLOYMENT_GUIDE.md and scripts/import_sqlite_data.py. The import script
   intentionally does not import users or device tokens. Recreate admin and register
   devices on the hosted website. Do not upload the local DB to GitHub.

PART D — REGISTER AND CONNECT AN ESP32
--------------------------------------
1. In the deployed website, sign in as administrator and open Devices.
2. Register a device. Choose a unique Device ID and display name. Use the public HTTPS
   site URL, e.g. https://YOUR-SERVICE.onrender.com (no /api suffix).
3. Copy the generated device token immediately and store it privately. The site does
   not display device tokens in the normal device list. Never put the token in a URL,
   screenshot, GitHub commit or Serial Monitor.
4. Install Arduino IDE and the Espressif ESP32 board package. Install ArduinoJson 7.x.
5. Open firmware/StreetWatchESP32/StreetWatchESP32.ino, select the correct ESP32 board
   (ESP32 Dev Module) and serial port, then compile and upload.
6. On first boot the ESP32 creates:
     Wi-Fi name: STREETWATCH-SETUP
     Password: SWneo- plus the final 6 hexadecimal characters of the ESP32 MAC address
     Setup page: http://192.168.4.1
   The MAC suffix is printed to Serial Monitor. The firmware does not print Wi-Fi
   passwords or device tokens.
7. Connect your phone to STREETWATCH-SETUP. If your phone says there is no internet,
   choose to stay connected. Open http://192.168.4.1 in a browser.
8. Enter the Wi-Fi SSID/password for the location where the rover will operate, the
   Render HTTPS URL, the exact Device ID and the token copied from Devices. Tap SAVE.
9. The ESP32 saves settings in Preferences/NVS and restarts into Wi-Fi station mode.
   Setup AP is not exposed during normal operation.
10. To reopen setup, hold a momentary button between GPIO4 and GND for 4 seconds.
    If Wi-Fi cannot reconnect for 120 seconds, firmware recovery mode opens the portal.
11. Return to the website Devices page and verify Online / Last contact. Test commands
    with wheels lifted, then verify the physical emergency stop before floor testing.

PART E — HOW REMOTE CONTROL WORKS
----------------------------------
Phone/PC browser -> Internet -> Render HTTPS Flask API <- outbound HTTPS polling <- ESP32

The ESP32 initiates outbound HTTPS requests from its own Wi-Fi network. No router port
forwarding, local PC IP address, or PC that stays on is required. Different ESP32 devices
can use different Wi-Fi networks while polling the same Render service. Each device uses
its own Device ID and token. Internet/server loss or stale commands must result in stop.
Keep a physical emergency stop independent of the website and internet.

FREE PLAN LIMITATIONS
---------------------
Render Free web services can sleep after inactivity, have cold-start delay and do not
provide guaranteed uptime or durable local disk. Free database offers have storage and
expiry limits that can change. Do not claim 24/7 control or permanent free data storage.
A sleeping/unavailable server means remote commands are unavailable; the firmware should
stop safely when commands become stale. Store backups and verify current provider terms.

TESTING LIMITATIONS
-------------------
Python/template/static checks do not prove hardware behavior or a live deployment.
Compile the firmware with the actual Arduino toolchain, test the AP portal on the real
ESP32, verify TLS on the target network, and test emergency-stop behavior with wheels
lifted before any driving test.
